# HARDWARE_WIRING.md — Схема подключения аппаратной части (MVP v1.0)

> Целевой стенд: **2 релейных модуля (4 канала каждый)**, 6 светодиодов светофора
> (по 3 на группу A и B), Raspberry Pi 4 Model B. Нумерация пинов — **BCM**.

---

## 1. Пины Raspberry Pi 4 (GPIO header, 40-pin), нумерация BCM

| Назначение | BCM pin | Физический контакт (header) | Цвет провода (рекоменд.) |
|---|---|---|---|
| 5V питания реле-модулей | — | `2` (5V) и/или `4` (5V) | красный |
| GND для реле-модулей | — | `6` (GND), `9` (GND), `14` | чёрный |
| IN1 — красный, фаза A | **GPIO 17** | `11` | жёлтый |
| IN2 — жёлтый, фаза A | **GPIO 27** | `13` | зелёный |
| IN3 — зелёный, фаза A | **GPIO 22** | `15` | синий |
| IN4 — красный, фаза B | **GPIO 23** | `16` | оранжевый (к модулю 2, IN1) |
| IN5 — жёлтый, фаза B | **GPIO 24** | `18` | оранжевый (к модулю 2, IN2) |
| IN6 — зелёный, фаза B | **GPIO 25** | `22` | оранжевый (к модулю 2, IN3) |

**Важно:** GPIO питание логики реле — 3.3 В. У большинства 4-канальных модулей
(типа SRD-05VDC-SL-C) входы IN совместимы с 3.3 В, но если модуль с JD-VCC —
убедитесь, что джемпер JD-VCC **снят** (раздельное питание), либо питайте
обмотки от 5V через отдельный источник. Иначе возможен нестабильный сигнал.

## 2. Схема релейного модуля и светодиодов

Каждый релейный модуль имеет контакты:

```
      Реле (1 канал)
  ---------- ----------
  |  LED_A | COM | NO |
  |        +-----+----+
  |   IN_X |      |NC |  (NO = normally-open, NC = normally-closed)
  |   GND   +----+----+
  |   VCC    |
  ---------- ----------
```

**Логика:** при `LOW` на `IN_X` реле замыкает `COM–NO`, светодиод загорается
(модуль активный LOW — это соответствует `relay_active_low: true` в конфиге).

**Подключение светодиода (имитация сигнала светофора) к одному каналу:**

```
        +3.3V (pin 1)          ┌── резистор 220–330 Ом ──┐
             │                                           │
             │                          Анод (+) светодиода
             │                                 │
             └──────────────────────────────────┴── Катод(-) → COM реле
                                              |
                                Светодиод светится при замкнутом COM-NO
                                              │
                                         NO → GND
```

Собирается **6 идентичных цепочек** (по одной на каждый сигнал):

| Светодиод | Канал реле (IN) | BCM pin в конфиге | Цвет светодиода |
|---|---|---|---|
| Красный A | Модуль1-IN1 | `pin_red_a: 17` | красный |
| Жёлтый A  | Модуль1-IN2 | `pin_yellow_a: 27` | жёлтый |
| Зелёный A | Модуль1-IN3 | `pin_green_a: 22` | зелёный |
| Красный B | Модуль2-IN1 | `pin_red_b: 23` | красный |
| Жёлтый B  | Модуль2-IN2 | `pin_yellow_b: 24` | жёлтый |
| Зелёный B | Модуль2-IN3 | `pin_green_b: 25` | зелёный |

> **Про резисторы:** для светодиода на 3.3В типичный ток 10–20 мА, номинал
> 220–330 Ом. Если светодиоды слишком тусклые/яркие — подберите в диапазоне
> 150–470 Ом. (При питании цепочек от 5V используйте резисторы от 330 Ом.)

## 3. Порядок подключения (пошагово)

1. **Обесточьте Raspberry Pi** — отключите питание перед монтажом.
2. Подключите питание модулей: `VCC` модуля 1 и 2 → контакт `2` (5V) и `4` (5V);
   `GND` обоих модулей → `6` / `9` (GND).
3. Шлейфы GPIO: `GPIO17→IN1`, `GPIO27→IN2`, `GPIO22→IN3` (модуль 1);
   `GPIO23→IN1`, `GPIO24→IN2`, `GPIO25→IN3` (модуль 2).
4. Соберите 6 светодиодных цепочек по п. 2 (резистор + светодиод + реле COM/NO).
5. Подайте питание на Pi (5.1V/3A). Убедитесь, что светодиоды не горят
   (все выводы в неактивном состоянии).
6. Проверьте камеру: `ls /dev/video*` (USB) или `libcamera-hello` (CSI).

## 4. Запуск pigpio-демона (рекомендуемый бэкенд GPIO)

```bash
# Установка (если ещё не установлен)
sudo apt update && sudo apt install -y pigpio python3-pigpio

# Запуск демона вручную
sudo pigpiod

# Или автозапуск при старте системы
sudo systemctl enable --now pigpiod

# Проверка, что демон работает и GPIO-контроллер виден
pigs t
```

> Если pigpiod не запущен — программа автоматически перейдёт на `RPi.GPIO`,
> а если запущена не на Raspberry Pi — на MOCK-эмуляцию (см. лог при старте).

## 5. Проверка (quick test)

```bash
cd smart-traffic-light
python3 - <<'PY'
import yaml, time
from gpio_controller import RelayController
cfg = yaml.safe_load(open("config.yaml"))
g = RelayController(cfg)
print("Backend:", g.backend)
g.apply_outputs({"A": "GREEN", "B": "RED"})
time.sleep(2)
g.apply_outputs({"A": "YELLOW", "B": "RED"})
time.sleep(1)
g.apply_outputs({"A": "RED", "B": "GREEN"})
time.sleep(2)
g.cleanup()
print("OK — все сигналы переключаются")
PY
```

При успехе вы последовательно увидите: зелёный A, жёлтый A, зелёный B.

## 6. Пошаговый запуск после подключения (Raspberry Pi)

После сборки схемы выполните по порядку:

```bash
# 1) активируйте окружение (если ещё не активировано)
cd ~/smart-traffic-light
source .venv/bin/activate

# 2) проверьте, что схема зажигает светодиоды (тест из раздела 5)
python3 - <<'PY'
import yaml, time
from gpio_controller import RelayController
g = RelayController(yaml.safe_load(open("config.yaml")))
print("Backend:", g.backend)          # должен быть pigpio или rpi
g.apply_outputs({"A": "GREEN", "B": "RED"}); time.sleep(1)
g.apply_outputs({"A": "RED", "B": "GREEN"}); time.sleep(1)
g.cleanup()
PY
# -> зелёный A, затем зелёный B

# 3) тест на заранее записанном видео (mock-камеры не требуется)
python3 main.py --config config.yaml
# 4) боевой режим на камере: в config.yaml поставьте mode: live, camera_source: 0
```

> Если в этом тесте `Backend: mock` и светодиоды не горят — проверьте питание
> модулей (5V), заземление (GND) и джемпер JD-VCC.

## 7. Настройка активного/пассивного уровня реле

Код по умолчанию считает реле **активным LOW**: срабатывает, когда GPIO выдаёт
`0` (GND). Это справедливо для большинства модулей с оптронами.

Если ваши реле, наоборот, включаются при `1` (`HIGH`) — поменяйте в `config.yaml`:
```yaml
gpio:
  relay_active_low: false   # было true
```
После изменения перезапустите программу.

## 8. Отладка ПОЛЬЗОВАТЕЛЮ без Raspberry Pi (ноутбук)

Подключение светодиодов к GPIO возможно **только** на Raspberry Pi.
На ноутбуке `RelayController` перейдет в MOCK-эмуляцию: он логирует
«включение» сигналов, но физически ничего не замыкает. Для отладки на
ноутбуке:

1. Установите зависимости (см. `USER_GUIDE.md`, Часть I).
2. Запустите `python main.py --config config.yaml` — в окне вы увидите
   переключение фаз и метрики PT, а в консоли — `GPIO-бэкенд: MOCK`.
3. Для тестов с GPIO-железом используйте Raspberry Pi (раздел 6 этой схемы).
